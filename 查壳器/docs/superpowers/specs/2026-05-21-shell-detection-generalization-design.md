# APK 查壳自动增强设计稿

## 1. 目标

将当前“厂商强特征命中才给结论”的查壳逻辑升级为分层识别引擎，尽量减少“遇到一个样本补一条规则”的维护方式。

升级后的引擎需要支持四类结论：

- `检测到 XX 加固`
- `疑似加固（偏向 XX 加固）`
- `疑似存在加固`
- `未识别到已知加固`

## 2. 设计思路

### 2.1 厂商家族层

保留现有厂商家族特征，但不再只做简单命中判断。每个家族由多条强/中/弱特征组成，通过加权评分决定是否直接判定为已识别厂商。

### 2.2 家族偏向层

当某个家族命中了部分特征，但分数不足以直接判定时，若该家族明显领先其他家族，则输出：

- `疑似加固（偏向 XX 加固）`

同时保留命中特征与说明，方便人工复核。

### 2.3 通用可疑壳簇层

新增一组不直接绑定厂商、但明显带有保护器/壳味道的通用指标，例如：

- dex loader / dex helper
- 风险壳 stub
- 保护器签名残留
- 常见壳式加密 so

当通用可疑分数达到阈值，但没有明确家族胜出时，输出：

- `疑似存在加固`

### 2.4 反误报层

仅包含常规业务资源、普通加密素材或常见 SDK 文件时，仍应保持：

- `未识别到已知加固`

避免因为 `encrypt`、`security` 等普通单词导致误报。

## 3. 数据模型

`ShellDetectionResult` 增加：

- `verdict`：用于 UI 展示的最终结论
- `rationale`：用于说明判定依据
- `disposition`：表示是已识别、疑似偏向、疑似未知还是未识别

保留：

- `vendor`
- `matchedFeatures`
- `confidence`

## 4. UI 展示

结果面板改为展示：

- 查壳结论：显示 `verdict`
- 置信度
- 判定说明：显示 `rationale`
- 命中特征

底部 `Shell` 文案同步改为使用 `verdict`，不再只显示“检测到/未检测到”两档。

## 5. 测试策略

新增三类回归测试：

- 家族偏向：仅命中部分娜迦/梆梆特征时，应返回“疑似加固（偏向 XX）”
- 通用可疑壳簇：命中 loader + 壳式辅助特征，但不够指向具体厂商时，应返回“疑似存在加固”
- 反误报：普通业务资源或弱关键词不应触发疑似加固
