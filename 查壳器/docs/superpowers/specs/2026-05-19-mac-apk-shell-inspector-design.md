# Mac APK 查壳器设计稿

## 1. 目标

构建一个适用于 macOS 的独立桌面应用，用于离线分析 APK 文件，识别常见加固厂商，并展示 APK 基础信息。应用需要具备以下特征：

- 双击即可运行，不依赖用户手动安装 Java、apktool、aapt 或 Android SDK
- 采用 Mac 原生风格界面
- 支持 Intel 与 Apple Silicon 通用分发
- 完全离线可用，不依赖任何网络服务
- 主界面交互参考传统单窗口工具，但整体视觉与交互符合现代 macOS 使用习惯

## 2. 范围

### 2.1 包含范围

- APK 文件选择与拖拽导入
- APK 基础信息提取
  - 应用包名
  - 应用版本名
  - 应用版本号
  - 最低 SDK / 目标 SDK（若可解析）
  - ABI 信息
  - 签名摘要
- 常见加固厂商识别
- 命中特征说明展示
- 最近打开文件记录
- 分析状态与错误提示
- 结果复制
- 打包为可直接分发的 `.app`

### 2.2 暂不包含

- 联网更新规则
- 云端识别
- APK 重打包、反编译 UI、代码浏览
- iOS IPA 分析
- 多标签页批量分析

## 3. 技术方案

### 3.1 总体方案

采用 `SwiftUI + 本地分析引擎` 架构：

- `SwiftUI` 负责桌面应用界面与系统交互
- `Analyzer Core` 负责 APK 结构读取、Manifest 解析、证书提取、ABI 识别
- `Shell Detector` 负责根据内置规则表执行查壳识别
- `Bundled Runtime Layer` 负责封装和调度应用包中自带的必要二进制或资源

该方案优先保证原生体验、离线可用和可分发性，避免引入 Electron/Tauri 之类会削弱原生感的技术栈。

### 3.2 依赖策略

优先使用原生代码直接解析 ZIP/APK 结构和标准文件内容，尽量减少外部工具依赖。

若部分能力难以稳定通过原生方式覆盖，则允许在应用包中内置最小化分析组件，但必须满足：

- 完全随应用打包
- 首次启动无需下载
- 用户无需额外配置环境变量
- 对 Intel 与 Apple Silicon 提供兼容方案

## 4. 架构设计

### 4.1 模块划分

#### App Shell

负责：

- 主窗口
- 文件选择
- 拖拽接收
- 最近文件
- 结果展示
- 复制结果
- 退出操作

#### Analyzer Core

负责：

- 校验 APK 是否为合法 ZIP/APK
- 提取 APK 条目列表
- 读取 Manifest、签名和库目录信息
- 输出统一结构化分析结果

#### Shell Detector

负责：

- 扫描规则特征
- 根据规则命中计算查壳结论
- 输出厂商名、命中特征、置信说明

#### Bundled Runtime Layer

负责：

- 定位 App Bundle 内自带资源
- 调用必要的本地辅助组件
- 管理临时工作目录

### 4.2 数据流

1. 用户选择或拖入 APK
2. App Shell 校验文件扩展名与可访问性
3. 文件复制或映射到临时分析工作区
4. Analyzer Core 提取基础信息
5. Shell Detector 执行规则匹配
6. 结果合并为统一视图模型
7. UI 展示查壳结论、基础信息、命中特征与状态

## 5. 界面设计

### 5.1 总体布局

主界面采用单窗口经典工具窗布局，结构如下：

- 顶部：APK 路径输入框 + “选择文件”按钮
- 中部：说明 / 分析摘要面板
- 底部：状态条 + “复制结果”按钮 + “退出”按钮

整体布局致敬用户提供的传统工具窗口，但视觉细节采用 macOS 原生控件与间距规范。

### 5.2 默认状态

默认状态下，中部面板展示：

- 工具用途说明
- 支持的加固识别类型说明
- 离线与隐私说明
- 支持拖拽导入提示

### 5.3 分析完成状态

分析完成后，中部面板切换为结果摘要，包括：

- 查壳结论
- 厂商名称或“未识别到已知加固”
- 包名
- 版本名 / 版本号
- ABI 信息
- 证书摘要
- 命中特征列表
- 分析耗时

### 5.4 状态条文案

状态条负责显示短句结果与进度，例如：

- 未选择 APK
- 正在分析 APK
- 正在读取 Manifest
- 正在匹配加固规则
- 检测到梆梆加固
- 未检测到已知加固
- APK 文件损坏或格式不合法

## 6. 功能设计

### 6.1 文件导入

支持两种方式：

- 通过文件选择器选择 `.apk`
- 将 `.apk` 拖入窗口

导入成功后自动触发分析，无需用户再次点击开始。

### 6.2 基础信息提取

基础信息提取目标如下：

- `packageName`
- `versionName`
- `versionCode`
- `minSdkVersion`
- `targetSdkVersion`
- ABI 列表
- 签名证书摘要（SHA-1 / SHA-256 至少展示一种稳定摘要）

若部分字段无法提取，则显示“不可用”而不是空白。

### 6.3 加固识别

第一版查壳基于规则匹配，不做机器学习或联网检测。

规则来源主要包括：

- 特征库文件名
- 目录结构
- Manifest 特征
- assets 特征
- META-INF 特征
- 已知 so 文件名

每条规则应输出：

- 厂商名
- 命中特征
- 说明
- 优先级

若多家厂商规则同时命中，则按优先级和命中特征数量决策，并保留“多重命中”说明。

### 6.4 最近文件

记录最近分析过的本地 APK 路径，数量控制在合理范围内（例如 10 条），仅保存在本机用户目录中，不上传。

### 6.5 复制结果

支持将当前分析结果复制为可读文本，方便用户直接发送给他人。复制内容至少包含：

- 文件名
- 查壳结论
- 基础信息摘要
- 命中特征

## 7. 错误处理

### 7.1 用户可见错误

所有错误提示必须使用人类可读文案，不直接暴露底层堆栈。

典型错误包括：

- 文件不存在或无权限读取
- 非 APK 文件
- APK 文件损坏
- 临时目录创建失败
- Manifest 无法解析
- 内置运行时异常

### 7.2 降级原则

- 基础信息部分提取失败时，只要 APK 仍可部分读取，允许继续执行查壳
- 查壳失败但基础信息可读时，仍展示基础信息，并将查壳结果标记为“分析失败”
- 任一单项失败不得导致应用崩溃退出

## 8. 打包与分发

### 8.1 分发目标

产出一个可以双击启动的 macOS `.app` 成品，后续可进一步封装为 `.dmg`。

### 8.2 架构支持

需要支持：

- Intel Mac
- Apple Silicon Mac

优先采用 Universal Binary 打包方式，确保同一安装包可覆盖两类机器。

### 8.3 自带依赖

应用包必须内置所有必要资源和辅助组件。安装完成后：

- 无需网络
- 无需命令行操作
- 无需单独安装运行时

## 9. 安全与隐私

- 所有分析仅在本地执行
- 不上传 APK
- 不收集遥测
- 最近文件仅保存路径记录，且仅保留在本机
- 临时分析目录在任务完成后尽可能清理

## 10. 测试策略

### 10.1 单元测试

覆盖以下模块：

- APK 文件基础校验
- Manifest 字段解析
- ABI 提取
- 签名摘要提取
- 单条查壳规则匹配
- 多规则冲突裁决

### 10.2 集成测试

使用一组已知样本 APK 验证：

- 未加固 APK
- 单一已知厂商加固 APK
- 非法或损坏 APK
- 缺少部分元信息的 APK

### 10.3 UI 测试

验证：

- 文件选择
- 拖拽导入
- 分析状态切换
- 错误提示显示
- 复制结果按钮

## 11. 第一版交付标准

第一版完成时，必须满足：

- 用户能双击打开应用
- 用户能拖入或选择 APK
- 应用能显示基础信息
- 应用能识别一批常见加固特征
- 应用在异常输入下不崩溃
- 应用全程离线可用

## 12. 已确认决策

- 产品形态：独立 Mac 桌面应用
- 风格：Mac 原生风格
- 功能范围：查壳 + APK 基础信息
- 分发方式：给别人也能双击打开
- 依赖策略：必须自带
- 兼容范围：通用版（Intel + Apple Silicon）
- 网络策略：必须离线
- 技术路线：SwiftUI + 自带分析引擎
- 界面方向：经典工具窗布局（Mac 原生化）
