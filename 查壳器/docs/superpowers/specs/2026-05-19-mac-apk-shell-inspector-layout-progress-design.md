# Mac APK 查壳器布局与进度条改版设计稿

## 1. 目标

在现有 Mac APK 查壳器基础上，完成一次界面重排与分析反馈升级，使产品更接近用户提供的经典工具窗口样式，同时补充可见的解析进度条与步骤文案，让用户知道当前具体解析到哪一步。

## 2. 本次改动范围

### 2.1 包含范围

- 将主窗口布局调整为接近参考图的经典工具窗口结构
- 顶部保留 `File + 路径输入框 + 浏览按钮` 组合
- 中部改为大块说明 / 结果面板
- 底部保留 `Shell + 结果文本 + Exit`
- 在底部结果区上方新增解析进度条
- 新增分步进度文案，例如“正在读取 AndroidManifest.xml（第 2/5 步）”

### 2.2 不包含范围

- 分析引擎核心算法重写
- 规则库扩充
- 新增联网能力
- 新增多文件批量解析

## 3. 布局设计

### 3.1 总体结构

窗口继续保持单窗口桌面工具形态，但改为更贴近参考图的纵向三区布局：

1. 顶部文件区
2. 中部说明 / 结果区
3. 底部状态区

整体观感目标不是复刻 Windows 旧控件，而是保留同样的信息组织方式，用 macOS 原生控件去表达。

### 3.2 顶部文件区

顶部采用单行结构：

- 左侧固定标签：`File`
- 中间路径输入框：展示当前 APK 路径
- 右侧按钮：采用短文案按钮或 `...` 风格浏览按钮

约束如下：

- 分析期间禁用浏览按钮
- 拖拽仍然保留，但视觉上不抢顶部文件区主入口
- 路径过长时允许中间截断或水平滚动，不强行换行

### 3.3 中部说明 / 结果区

中部保留大块矩形面板，分两种状态：

- 默认状态：显示支持厂商说明、离线说明、拖拽提示
- 结果状态：显示基础信息、命中特征、证书摘要、ABI、耗时

这块的视觉目标是“像参考图一样是一整块内容区”，而不是当前版本那种偏卡片式信息区。

### 3.4 底部状态区

底部结构改为三层：

1. 进度文案
2. 进度条
3. `Shell + 结果文本 + Exit`

采用用户选定的 `B` 方案，也就是把进度反馈集中放在底部结果区上方，而不是塞到中部说明区顶部。

这样做的原因：

- 更贴近参考图原始结构
- 不破坏中部说明区的整体阅读性
- 让“解析中”和“最终结论”在同一视觉区域衔接，更符合工具软件习惯

## 4. 进度反馈设计

### 4.1 进度模型

第一版采用固定步骤进度，而不是根据文件大小或真实字节流动态估算。

推荐拆成 5 步：

1. 校验 APK 文件
2. 读取 AndroidManifest.xml
3. 提取 APK 基础信息
4. 匹配加固规则
5. 整理并展示结果

每一步都提供：

- 当前步骤标题
- 步骤序号，如 `第 2/5 步`
- 百分比进度

### 4.2 进度条行为

进度条仅在分析过程中显示为活跃状态：

- 开始分析时重置为 0%
- 每完成一个步骤推进到对应百分比
- 成功后推进到 100%
- 失败时停在当前步骤，并保留失败文案

如果分析极快，仍然保留步骤切换，但不强制人为延迟。

### 4.3 进度文案

进度文案必须具体，避免只显示“正在分析”这种空话。示例：

- 正在校验 APK 文件（第 1/5 步）
- 正在读取 AndroidManifest.xml（第 2/5 步）
- 正在提取基础信息（第 3/5 步）
- 正在匹配加固规则（第 4/5 步）
- 正在整理结果（第 5/5 步）

失败时改为：

- 解析失败：APK 文件损坏
- 解析失败：未找到 AndroidManifest.xml

## 5. 状态切换规则

### 5.1 默认态

- 中部展示说明文本
- 底部结果文本展示默认提示
- 进度条为空或隐藏

### 5.2 解析中

- 顶部文件路径锁定
- 中部维持说明区或切换为“正在解析”辅助说明
- 底部进度条显示
- `Shell` 结果文本显示“正在分析”

### 5.3 成功态

- 中部展示结构化结果
- 进度条到 100%
- `Shell` 结果文本显示厂商结论或“未识别到已知加固”

### 5.4 失败态

- 中部展示错误说明
- 进度条停留在失败步骤
- `Shell` 结果文本显示失败摘要

## 6. 交互与实现边界

### 6.1 交互要求

- 用户点按钮选文件后自动解析
- 用户拖入文件后自动解析
- 分析期间禁重复提交
- 用户能直接从进度区看见当前步骤

### 6.2 实现建议

为了降低改动成本，本次不重写分析引擎，只在 ViewModel 与分析流程外层新增显式阶段汇报机制：

- ViewModel 维护 `progressValue`
- ViewModel 维护 `progressLabel`
- Analyzer 外层按阶段推进进度
- 核心分析逻辑仍复用当前 `APKAnalyzer`

这意味着第一版进度条反映的是“流程阶段进度”，不是“字节级真实进度”。这对当前工具型产品已经足够，而且稳定。

## 7. 测试策略

需要新增或调整测试：

- ViewModel 进度文案映射测试
- ViewModel 成功流程进度归零到完成测试
- ViewModel 失败时停留在当前步骤测试
- 结果文案在底部状态区的回归测试

## 8. 完成标准

本次改版完成时，必须满足：

- 主界面结构明显贴近参考图
- 进度条位于底部结果区上方
- 用户能看见明确的步骤文案
- 分析成功和失败时进度反馈都正确
- 原有拖拽、文件选择、复制结果能力不被破坏

## 9. 已确认决策

- 布局方向：接近参考图的经典工具窗口结构
- 进度条方案：`B`，放在底部结果区上方
- 文案语言：中文
- 进度模型：固定五阶段流程进度
